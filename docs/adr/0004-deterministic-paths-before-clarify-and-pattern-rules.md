# 确定性直答优先于 LLM 澄清追问；规则排除用「模式」不用「词」

admin 全库最近订单直答（`pipeline/admin_recent.py`）最初把"消息含 旅客/用户/客户/乘客/我 任一字样"一律排除，导致 A02「列出系统里最近订单，并说明每条订单属于哪位旅客用户名」被误判为"查指定旅客"，跳过直答；同时路由低置信度的澄清追问分支排在 admin 直答之前，最终对用户返回一句追问而不是订单列表。这是同一问题的两个层次：**规则用词排除造成误伤**，**LLM 概率判断抢跑了确定性规则**。

决策：

1. **确定性路径在代码结构上先于 LLM 兜底**：admin 查指定旅客、admin 查最近订单等直答路径提前到路由澄清追问分支之前执行。确定性规则优先不靠"恰好没触发澄清"，而是靠执行顺序保证。
2. **排除条件从「词出现」改为「结构模式」**：仅当出现「旅客/用户/客户/乘客 + 英文名」这类指定旅客表达时才交给 admin_customer；泛指表达（如"旅客用户名"）不排除，继续命中最近订单直答。
3. **admin 无代客目标时保留 `list_bookings` 工具回退**：注入数据不完整或直答未命中时，模型仍可调工具取最新列表，避免答不出。

被否决的方案：① 恢复"提示模型先调用 list_bookings"（`b351736` 之前）——那是 prompt 约束，违背 binder"数据边界靠注入"的原则；② 继续用宽排除词并依赖路由恰好高置信——会把"旅客用户名"这类泛指误伤，且脆弱。

预防机制（此类问题的统一处理方式）：

- 规则改动必须配**正反例单测**：每个排除条件都要问"我排的是词还是模式"，并在 `tests/test_admin_recent.py` 固化正反例；
- **确定性路径在编排层优先级永远高于 LLM 兜底**，代码结构上保证，不依赖路由置信度；
- 修改路由/直答规则后必须跑 `pytest` + 37 题 eval 回归（A02/T03 即回归用例）；
- 翻车案例持续记入本目录，改规则前先查历史 ADR。
